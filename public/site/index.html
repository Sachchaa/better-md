What it is

better-md is two things that fit together. The first is a Markdown editor: edit the source on the left or the rendered preview on the right, and both stay in sync. Three layouts, light and dark themes, synced scrolling, export to Markdown or PDF.

The second is better-md, a command that opens real files from your machine in it. Coding agents write a lot of Markdown — plans, specs, notes — and reading those in a terminal pager or a raw text buffer wastes what they are. One command opens the file you actually care about, properly rendered, and Cmd+S writes your edits back to disk.

It runs entirely on your machine. There is no account, no sync service, and no server to send your documents to.

How it works

Browsers cannot open arbitrary files from disk — that restriction is the whole reason a web-based editor normally can't touch your work. The CLI closes the gap by becoming a small local server the editor talks to. 

$ better-md --plan
   │
   ├─ resolve one directory as the workspace
   ├─ start http://127.0.0.1:<ephemeral port>
   │    ├─ serve the editor from assets embedded in the binary
   │    ├─ GET/PUT /api/doc     documents, through a path-confinement gateway
   │    └─ GET     /api/events  change notifications (SSE)
   ├─ watch the workspace for changes
   └─ open your browser at .../?t=<token>

Everything is scoped to that one directory. A fresh 32-byte token is minted per run and never written to disk. The editor's own files are embedded into the binary at build time, which is what makes a single self-contained executable possible — and it removes a whole class of bug as a side effect: the route that serves the editor resolves no paths and opens no files, so a request either names an embedded asset or it 404s.

Saving is explicit

Nothing is written until you press Cmd+S. Auto-save would rewrite plan files on every stray keystroke.

Each save carries the modification time the document was loaded at. If the file moved on disk in the meantime, the write is refused rather than silently winning, and you choose: keep yours, or take the version on disk. If the file was deleted rather than changed, there is no version to take — so the editor says so and keeps your buffer, because that buffer is now the only copy.

It keeps up with your agent

The CLI watches the workspace and streams changes to the editor, so a plan updates on screen while an agent is still rewriting it. With no unsaved edits, the document just refreshes. With unsaved edits, you get a conflict banner and nothing is overwritten in either direction until you pick.

Safe by construction

  • Binds to 127.0.0.1 only — never a routable interface.
  • Every /api/* request needs the run's token, compared in constant time, and sent as a header so it cannot leak through a URL.
  • File access is confined to the workspace directory, checked after resolving symlinks, and limited to Markdown and text extensions.
  • Requests carrying a foreign Origin are refused.
  • The token is stripped from the address bar at boot, so it never reaches your history.

Commands

Command What it opens
better-md --plan Claude Code's plans from ~/.claude/plans, with the newest one active
better-md notes.md A single file
better-md ./docs Every Markdown file in a directory
better-md --port 4321 A fixed port instead of an ephemeral one
better-md --no-open Print the URL without launching a browser

btr-md is a shorter alias for the same binary, and each name reports itself in --help and in error messages.

Install

$ curl -fsSL https://better-md.dev/install.sh | sh

The installer picks the right build for your platform, verifies it against the published SHA256SUMS — and refuses to install if that does not match, or if the checksums are missing — then drops it in ~/.local/bin.

Prefer to read it first? It is served as plain text, so better-md.dev/install.sh opens in a browser, and the copy on GitHub is identical. To uninstall, delete the two files it reports. There is nothing else on disk.

Or skip installing altogether and try the editor in your browser — it runs with sample documents, since opening your own files is exactly the part that needs the local command.
